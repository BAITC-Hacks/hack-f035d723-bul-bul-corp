# AI Sana backend

FastAPI + SQLite. Backend реализует сценарий задания AI Sana: черновик → вопросы → редактируемая карточка → ручное подтверждение → рейтинг → публикация → отклик → ручной выбор → результат → проверка → баллы команды.

Платформа не ограничена продажами или одной отраслью. В демонстрационных данных пять разных потребностей: распределение обращений, поиск учебных материалов, маршруты доставки, поиск пунктов переработки и запись на оборудование. Пример ниже — одна задача пользователя, а не назначение всей платформы.

Это описание backend, не утверждение о готовности frontend из других веток. Контракт и изменения для frontend/QA: [CONTRACT.md](CONTRACT.md), точные схемы: [openapi.json](openapi.json).

## Аккаунты и профили, API 1.2

Реализованы регистрация и вход, серверные сессии с HttpOnly-cookie, выход, смена пароля с отзывом всех сессий, личные данные и редактируемые профили бизнеса/команды. Владение задачами и предложениями определяется по профилю из сессии. Email для входа не публикуется. Демоавторизация выключена по умолчанию и включается только через `DEMO_MODE=true`.

Контракт для экранов: [ACCOUNTS.md](ACCOUNTS.md). Состав интеграционной ветки, порядок объединения, браузерное QA и пятиминутный показ: [HANDOFF.md](HANDOFF.md).

Сервер остановлен, тестовая база удалена. Внешний AI и браузерный frontend в этой проверке не использовались.

## Проверка по заданию AI Sana, 2026-09-23

Проверен и исправлен существующий backend. Frontend исключён из этой проверки по запросу владельца.

| Требование задания | Результат проверки backend |
|---|---|
| Свободное описание, минимум три вопроса, редактирование и подтверждение | Описание принимается в need/context; вопросы, compose, PATCH и confirm работают. Полная карточка получает содержательные уточнения о данных и пользователях |
| Все поля карточки | Название, контекст, потребность, пользователи, данные, ограничения, результат, критерии, контакт и взаимодействие есть в TaskFields; тема хранится отдельно |
| Рейтинг 0–100 с расшифровкой и пересчётом | Веса соответствуют заданию; баллы начисляются после подтверждения. Сквозной тест проверяет рост 10 → 100 и сумму категорий |
| Общий каталог, сортировка, фильтры, отклики при низком рейтинге | Проверены сортировка по опубликованному рейтингу, фильтры topic/level и отклик на опубликованную задачу с низким рейтингом |
| Ручной выбор одной, нескольких или ни одной команды | Отклики создаются pending. Выбор и отклонение выполняет владелец; выбор одного отклика не меняет остальные. Лимита откликов нет |
| Баллы за фактический прогресс | До подтверждения этапа 0, после подтверждения 10. Повторное подтверждение не добавляет баллы |
| AI или допустимая локальная заглушка | Промпты, форматы и fallback доступны в ai.py. Ошибки провайдера и сохранение исходных фактов проверены с MockTransport; внешних AI-запросов в этой проверке не было |
| Минимальные исходные данные | Пять черновиков, пять карточек с рейтингами, пять команд с интересами/навыками/технологиями и пять откликов с идеей, планом, сроком и ссылкой |
| Запуск и демонстрация | Инструкция запуска ниже; HTTP-сценарий в корневом README. Полный путь от слабого описания до баллов команды закреплён тестом test_assignment_scenario_from_weak_description_to_earned_points |

Исправлено поведение compose: пустой запрос или повтор сохранённых ответов не сбрасывает подтверждение, рейтинг и версию. Если непустой ответ невозможно перенести в карточку, API возвращает 422 `unassigned_answers` с указанием вопроса и не сохраняет запрос частично. После исправления вопроса тот же ответ сохраняется целиком. Контракт ответа TaskResponse не изменён.

Проверка: `py -m unittest backend.test_ai backend.test_tasks backend.test_workflow backend.test_rating`, **47 тестов, OK**. Тесты используют отдельные временные SQLite-базы. Это подтверждение backend-сценариев; готовность пользовательского интерфейса и демонстрация в браузере здесь не оценивались.

## Конфигурация и OpenAI

Локальный `.env` находится в корне репозитория, исключён из Git и больше не отслеживается. `.env.example` содержит пустой `AI_API_KEY=`. Переменные процесса имеют приоритет. После изменения `.env` перезапустите backend. Старый ключ уже попал в историю (коммит `e78608f`): его необходимо отозвать у провайдера и выпустить новый; удаления файла недостаточно. Новый ключ храните только локально, не передавайте через репозиторий.

```dotenv
AI_API_KEY=ваш_секретный_ключ
AI_MODEL=gpt-4o-mini
AI_BASE_URL=https://api.openai.com/v1
AI_TIMEOUT_SECONDS=15
```

Также поддерживается `OPENAI_API_KEY`, если AI_API_KEY пуст. `DATABASE_PATH` задаёт путь к SQLite; по умолчанию `backend/sana.sqlite3`. Ключ не включается в API-ответы для frontend. Не копируйте ключ в клиентский код, README или отчёты QA.

Для вопросов OpenAI Chat Completions вызывается со Structured Outputs (`json_schema`, `strict: true`): схема разрешает только строки из текущего каталога и от 3 до 5 элементов. Для сборки карточки сохранён JSON-режим. Используются таймаут 15 секунд по умолчанию и отсутствие автоматических повторов. `gpt-4o-mini` поддерживает этот формат; другой провайдер/модель должны поддерживать строгую JSON Schema, иначе вопросы перейдут в безопасный fallback без повторного запроса в менее строгом режиме. Источник конкретного ответа виден в заголовке `X-AI-Source: openai|fallback`, который доступен frontend через CORS. HTTP 200 с fallback не доказывает успешный вызов OpenAI.

**Повторная реальная AI-приёмка после исправления каталога:** полностью заполненная карточка три раза подряд получила 3 разных разрешённых уточнения и `X-AI-Source: openai`. Карточки с одним, двумя и множеством недостающих полей, `/compose`, уточнение, повтор ответа и смысловая классификация свободного ответа также проверены реальными вызовами `gpt-4o-mini`. Отдельный запуск без ключа сохранил fallback и атомарный отказ `422 unassigned_answers`. Все 57 backend-тестов прошли. Вызовы выполнены на временных базах с синтетическими сведениями; рабочая база не изменялась. По решению владельца существующий ключ настроен в игнорируемом локальном `.env`; обычный запуск больше не требует извлечения ключа из истории в память. Ключ не добавлен в Git, но риск его прежней публикации остаётся: для устранения риска необходимы отзыв и замена у провайдера. Уже запущенный backend нужно перезапустить.

### Промпты и формат AI

Полный текст промптов находится в `backend/ai.py`.

- Вопросы: вход `task`, `missing_fields`, `allowed_questions`; ответ `{"questions":[string,string,string]}`, 3–5 разных уместных вопросов из каталога. Каталог передаётся как `enum` в строгой JSON Schema: модель не может заменить разрешённое уточнение собственной формулировкой. Промпт задаёт точное число вопросов для текущего раунда и запрещает перечислять весь каталог; оставшиеся вопросы откладываются. Недостающие сведения определяет общая с рейтингом функция `field_readiness`, независимо от подтверждения: непустое «не знаю», неизмеримый критерий или контакт без канала всё ещё требуют ответа. Приоритет — данные, пользователи, результат и критерии, затем остальные содержательные поля; название и тема откладываются, пока есть пробелы в содержании. При менее чем трёх недостающих полях добавляются уточнения к ним; для полной карточки каталог содержит только уточнения, без повторных базовых вопросов. Сервер независимо проверяет число и уникальность вопросов, принадлежность каталогу и наличие вопросов о недостающих полях, когда их меньше трёх.
- Сборка: вход модели `current`, `unassigned_answers`; ответ содержит ровно все 11 строковых полей TaskFields. Сервер заранее добавляет известные ответы целиком через перевод строки, сохраняя прежний текст, отрицания и условия; повтор того же ответа не добавляет дубликат. Модель получает уже объединённую карточку без дублирующих массивов известных ответов. Непустые значения копируются дословно, включая «не знаю» и последующие уточнения. Только пустое поле может получить целый однозначно классифицированный ответ из `unassigned_answers`; без таких ответов модель возвращает `current` без изменений. При отказе провайдера локальная сборка сохраняет то же объединение.
- Нет автоматических подтверждения, публикации, рейтинга или выбора команды моделью.
- При ошибке/невалидном JSON/дубликатах/выдуманном тексте используется локальный режим. Локальная сборка понимает предлагаемые вопросы ко всем полям, включая контакт и консультации. Если непустой ответ остаётся нераспределённым, HTTP endpoint отклоняет всю сборку с 422 unassigned_answers и указывает проблемный вопрос в field_errors. Частичных изменений карточки нет; пользователь может выбрать вопрос из /questions или внести сведения через PATCH.
- Проверка цитат защищает от добавления нового текста, но не доказывает правдивость исходных сведений или безошибочную смысловую классификацию. Поэтому карточка остаётся редактируемой и подтверждается человеком.

Ошибки внешнего провайдера (включая 401, 429, 500 и таймаут), отказ модели, оборванный ответ, некорректный JSON/структура, дубли вопросов или неподтверждённые текстом пользователя факты приводят к локальному результату и `X-AI-Source: fallback`. Текст исключения и ответ провайдера клиенту не раскрываются. В штатном fallback HTTP-ответ остаётся успешным; ошибки входного API-запроса обрабатываются отдельно по CONTRACT.md.

## Архитектура и сохранение

- `main.py`: HTTP API, права, SQLite-транзакции, миграция старых данных.
- `schemas.py`: строгие запросы и точные ответы OpenAPI.
- `rating.py`: одна детерминированная формула на сервере.
- `ai.py`: OpenAI и локальный режим, промпты и валидация.
- `seed.py`: загрузка/сброс синтетического набора.
- `fixtures/demo-identities.json`: два бизнеса, пять команд с интересами, навыками, технологиями.
- `fixtures/demo-data.json`: пять черновиков разной полноты, пять полных по набору полей карточек с рассчитанными рейтингами, пять откликов.

База создаётся автоматически. Текущие и опубликованные сведения/оценки разделены. Поля, рейтинг, номер и время публикации сохраняются вместе. Соединения закрываются, операции изменения выполняются в транзакции; AI-сеть не держит блокировку базы, изменение карточки за время compose вызывает 409 вместо потери правок.

При обновлении старой базы новые колонки добавляются автоматически. Старые дубли этапов сначала полностью сохраняются в `milestone_legacy_archive`; активным остаётся последний подтверждённый, иначе последний отправленный этап. Сумма корректируется до одного начисления 10 на предложение. Старые записи не теряются бесследно. Исторические номера/время публикации, которых раньше не было, инициализируются доступными метаданными; точное прошлое время восстановить невозможно. Оценки пересчитываются по текущей формуле отдельно для редактируемого и опубликованного текста.

Перед обновлением существующей базы остановите сервер и сделайте копию `sana.sqlite3`. Не удаляйте пользовательскую базу ради проверки или демонстрации.

## Правила рейтинга

| Категория | Баллы | Проверка |
|---|---:|---|
| Контекст и потребность | 20 | По 10 за context и need со сведениями без явной неопределённости |
| Данные и материалы | 20 | data_materials со сведениями без явной неопределённости |
| Ожидаемый результат | 15 | expected_result со сведениями без явной неопределённости |
| Измеримые критерии | 15 | Метрика с числом/единицей, измеримое количество объектов или результат с числовым сроком |
| Ограничения | 10 | constraints со сведениями без явной неопределённости |
| Пользователи | 10 | users со сведениями без явной неопределённости |
| Связь с бизнесом | 10 | 5 за контакт установленного формата + 5 за вид взаимодействия и канал/периодичность/доступность |

Принимаются: `10 заявок за 7 дней`, `точность 90%`, `Время ответа не более 2 секунд`. Дополнительно распознаются конструкции «действие + название показателя + изменение/цель с единицей» и «название показателя + явная граница с единицей»: `Снизить дефицит на 20%`, `Увеличить урожайность на 15%`, `Сократить потребление воды на 100 литров`, `Доля возвратов не более 2%`. Названия показателей не ограничены словарём отраслей. Поддерживаются русские/английские действия и границы, проценты, время, валюта, масса, объём и кВт·ч. Не принимаются: `kpi 1`, отдельное `90%`, дата, версия, цель без единицы или названия показателя. Контакт: email/телефон/@handle/HTTP(S). Консультации: например, `Еженедельный созвон; обратная связь в Telegram`. Это прозрачные лексические правила, не оценка истинности или экономической ценности. Полный набор поддерживаемых формулировок и тестовые примеры в rating.py/test_rating.py.

Явные сообщения о неизвестных, не определённых или требующих уточнения сведениях не приносят баллы: например, `Не знаю`, `Пока неизвестно`, `Ещё не определено`, `Требуется уточнение`, `TBD`, `I don't know`. Проверка применяется ко всем оцениваемым полям, до проверки метрик и контактов. Предложения и отдельные строки с такими маркерами исключаются из оценки; самостоятельные известные факты в других предложениях/строках учитываются. Поэтому добавленный после `Пока неизвестно` конкретный ответ может повысить рейтинг после подтверждения. Явное отсутствие ресурса (`Данных нет`, `Ограничений нет`) — известный факт, не неопределённость. `basis` объясняет отсутствие содержательных сведений, категория попадает в `missing`. Это консервативные лексические правила, не универсальное понимание текста; минимального порога длины нет.

До подтверждения баллы текущей версии равны нулю. Редактирование требует нового подтверждения; удаление сведений снижает рейтинг. AI формулу не изменяет. В ответе всегда итог, уровень, семь категорий с основаниями и список недостающих категорий.

Уровни: `draft` 0–39, `working` 40–69, `ready` 70–89, `priority` 90–100. Опубликованная задача любого уровня доступна всем командам. Каталог сортируется по опубликованному рейтингу и фильтруется по `topic` и `level`.

## Отклики, этап и баллы

Бизнес может выбрать ноль, одну или несколько команд. Выбор одного отклика не отклоняет остальные; автоматического назначения нет. Число откликов не ограничено. Идея/план/срок обязательны и непробельные; прототип необязателен, но непустая ссылка должна быть HTTP(S).

Один демонстрационный этап на выбранное предложение. Команда отправляет описание и ссылку; бизнес подтверждает либо возвращает с комментарием. Пересдача обновляет тот же ID. Подтверждение после возврата невозможно до пересдачи. После отправки результата менять выбор команды нельзя. Подтверждённый этап нельзя открыть повторно или заменить другим результатом. Повтор идентичного запроса возвращает прежний результат, параллельные запросы не создают дублей.

Подтверждение даёт 10 баллов, один раз. Это решение нашего backend-плана, не фиксированное число общего ТЗ. Кабинеты получают вложенный `milestone` из GET-списков предложений; команда дополнительно получает `team_points`. После перезапуска не требуется помнить ответы POST на клиенте.
