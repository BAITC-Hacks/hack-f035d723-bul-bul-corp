# AI Sana backend

FastAPI + SQLite. Backend реализует сценарий из `01-BACKEND.md`: черновик → вопросы → редактируемая карточка → ручное подтверждение → рейтинг → публикация → отклик → ручной выбор → результат → проверка → баллы команды.

Платформа не ограничена продажами или одной отраслью. В демонстрационных данных пять разных потребностей: распределение обращений, поиск учебных материалов, маршруты доставки, поиск пунктов переработки и запись на оборудование. Пример ниже — одна задача пользователя, а не назначение всей платформы.

Это описание backend, не утверждение о готовности frontend из других веток. Корневой README принадлежит QA и не редактировался. Контракт и изменения для frontend/QA: [CONTRACT.md](CONTRACT.md), точные схемы: [openapi.json](openapi.json).

Команды выполняются из корня репозитория, не из `C:\Users\Janchik`:

```powershell

.\.venv\Scripts\python.exe -m backend.seed
```

Для разработки допустим `--reload`. Для других компьютеров в доверенной локальной сети: `--host 0.0.0.0`, frontend обращается к IP компьютера, не к своему localhost. Демоидентичность не является защитой; не выставляйте сервис с реальными данными в публичный интернет.

- Swagger: http://localhost:8000/docs
- Проверка сервиса: http://localhost:8000/api/health
- Список профилей: http://localhost:8000/api/demo-identities
- Для API передавайте `X-Demo-Identity`: `business-demo`, `business-second`, `team-alpha`, `team-beta`, `team-gamma`, `team-delta`, `team-epsilon`.
- Python 3.10+ по синтаксису; фактически проверено на Python 3.14.

## Конфигурация и OpenAI

`.env` находится в корне репозитория и по явному решению владельца включён в Git для передачи QA вместе с ключом. Правило `.gitignore` не защищает уже отслеживаемый файл. Образец без ключа: `.env.example`. Переменные процесса имеют приоритет. После получения или изменения `.env` перезапустите backend. После проверки ключ следует отозвать; удаление файла не удаляет его из истории Git.

```dotenv
AI_API_KEY=ваш_секретный_ключ
AI_MODEL=gpt-4o-mini
AI_BASE_URL=https://api.openai.com/v1
AI_TIMEOUT_SECONDS=15
```

Также поддерживается `OPENAI_API_KEY`, если AI_API_KEY пуст. `DATABASE_PATH` задаёт путь к SQLite; по умолчанию `backend/sana.sqlite3`. Ключ не включается в API-ответы для frontend. Не копируйте ключ в клиентский код, README или отчёты QA.

OpenAI Chat Completions вызывается с JSON-режимом, таймаутом 15 секунд по умолчанию, без автоматических повторов. Источник конкретного ответа виден в заголовке `X-AI-Source: openai|fallback`, который доступен frontend через CORS. HTTP 200 с fallback не доказывает успешный вызов OpenAI.

**Ключ настроен; внешний AI проверен частично.** На временной БД с реальными вызовами SDK `/compose` вернул HTTP 200 и `X-AI-Source: openai`, сохранил переданные ответы и оставил карточку неподтверждённой/неопубликованной. `/questions` вернул HTTP 200 и `fallback`: модель выдала 8 вопросов вместо допустимых 3–5. Отдельный диагностический вызов подтвердил причину: все 8 вопросов допустимы и различны, но превышают лимит. Сервер корректно возвращает 5 локальных вопросов. Успешная внешняя генерация вопросов остаётся неподтверждённой; наличие ключа и HTTP 200 не означают успех обоих AI-endpoints.

### Промпты и формат AI

Полный текст промптов находится в `backend/ai.py`.

- Вопросы: вход `task`, `missing_fields`, `allowed_questions`; ответ `{"questions":[string,string,string]}`, 3–5 разных уместных вопросов из каталога. Модель выбирает вопросы по карточке, сервер проверяет допустимость. Локальный режим сначала спрашивает про отсутствующие поля, затем уточняет детали, если их меньше трёх.
- Сборка: вход `current`, `answers`, `assigned_answers`, `unassigned_answers`; ответ содержит ровно все 11 строковых полей TaskFields. Поля без данных остаются пустыми. Ответы на предлагаемые вопросы, включая уточнения к непустым полям, добавляются целиком через перевод строки с сохранением прежнего текста, отрицаний и условий. Повтор того же ответа не добавляет дубликат. Перед запросом к модели сервер уже объединяет известные ответы с текущими полями; модель не может удалить эти сведения. При отказе провайдера локальная сборка сохраняет то же объединение.
- Нет автоматических подтверждения, публикации, рейтинга или выбора команды моделью.
- При ошибке/невалидном JSON/дубликатах/выдуманном тексте используется локальный режим. Локальная сборка понимает предлагаемые вопросы ко всем полям, включая контакт и консультации. Для неизвестных вопросов неоднозначные сведения остаются нераспределёнными.
- Проверка цитат защищает от добавления нового текста, но не доказывает правдивость исходных сведений или безошибочную смысловую классификацию. Поэтому карточка остаётся редактируемой и подтверждается человеком.

Ошибки внешнего провайдера (включая 401, 429, 500 и таймаут), отказ модели, оборванный ответ, некорректный JSON/структура, дубли вопросов или неподтверждённые текстом пользователя факты приводят к локальному результату и `X-AI-Source: fallback`. Текст исключения и ответ провайдера клиенту не раскрываются. В штатном fallback HTTP-ответ остаётся успешным; ошибки входного API-запроса обрабатываются отдельно по CONTRACT.md.

## Архитектура и сохранение

- `main.py`: HTTP API, права, SQLite-транзакции, миграция старых данных.
- `schemas.py`: строгие запросы и точные ответы OpenAPI.
- `rating.py`: одна детерминированная формула на сервере.
- `ai.py`: OpenAI и локальный режим, промпты и валидация.
- `seed.py`: загрузка/сброс синтетического набора.
- `fixtures/demo-identities.json`: два бизнеса, пять команд с интересами, навыками, технологиями.
- `fixtures/demo-data.json`: пять черновиков разной полноты, пять полных по набору полей карточек с рассчитанными рейтингами, пять откликов.

База создаётся автоматически. Текущие и опубликованные сведения/оценки разделены. Поля, рейтинг, номер и время публикации сохраняются вместе. Соединения закрываются, операции изменения выполняются в транзакции; AI-сеть не держит блокировку базы, изменение карточки за время compose вызывает 409 вместо потери правок.

При обновлении старой базы новые колонки добавляются автоматически. Старые дубли этапов сначала полностью сохраняются в `milestone_legacy_archive`; активным остаётся последний подтверждённый, иначе последний отправленный этап. Сумма корректируется до одного начисления 10 на предложение. Старые записи не теряются бесследно. Исторические номера/время публикации, которых раньше не было, инициализируются доступными метаданными; точное прошлое время восстановить невозможно. Оценки пересчитываются по текущей формуле отдельно для редактируемого и опубликованного текста.

Перед обновлением существующей базы остановите сервер и сделайте копию `sana.sqlite3`. Не удаляйте пользовательскую базу ради проверки или демонстрации.

## Правила рейтинга

| Категория | Баллы | Проверка |
|---|---:|---|
| Контекст и потребность | 20 | По 10 за context и need со сведениями без явной неопределённости |
| Данные и материалы | 20 | data_materials со сведениями без явной неопределённости |
| Ожидаемый результат | 15 | expected_result со сведениями без явной неопределённости |
| Измеримые критерии | 15 | Метрика с числом/единицей, измеримое количество объектов или результат с числовым сроком |
| Ограничения | 10 | constraints со сведениями без явной неопределённости |
| Пользователи | 10 | users со сведениями без явной неопределённости |
| Связь с бизнесом | 10 | 5 за контакт установленного формата + 5 за вид взаимодействия и канал/периодичность/доступность |

Принимаются: `10 заявок за 7 дней`, `точность 90%`, `Время ответа не более 2 секунд`. Дополнительно распознаются конструкции «действие + название показателя + изменение/цель с единицей» и «название показателя + явная граница с единицей»: `Снизить дефицит на 20%`, `Увеличить урожайность на 15%`, `Сократить потребление воды на 100 литров`, `Доля возвратов не более 2%`. Названия показателей не ограничены словарём отраслей. Поддерживаются русские/английские действия и границы, проценты, время, валюта, масса, объём и кВт·ч. Не принимаются: `kpi 1`, отдельное `90%`, дата, версия, цель без единицы или названия показателя. Контакт: email/телефон/@handle/HTTP(S). Консультации: например, `Еженедельный созвон; обратная связь в Telegram`. Это прозрачные лексические правила, не оценка истинности или экономической ценности. Полный набор поддерживаемых формулировок и тестовые примеры в rating.py/test_rating.py.

Явные сообщения о неизвестных, не определённых или требующих уточнения сведениях не приносят баллы: например, `Не знаю`, `Пока неизвестно`, `Ещё не определено`, `Требуется уточнение`, `TBD`, `I don't know`. Проверка применяется ко всем оцениваемым полям, до проверки метрик и контактов. Предложения и отдельные строки с такими маркерами исключаются из оценки; самостоятельные известные факты в других предложениях/строках учитываются. Поэтому добавленный после `Пока неизвестно` конкретный ответ может повысить рейтинг после подтверждения. Явное отсутствие ресурса (`Данных нет`, `Ограничений нет`) — известный факт, не неопределённость. `basis` объясняет отсутствие содержательных сведений, категория попадает в `missing`. Это консервативные лексические правила, не универсальное понимание текста; минимального порога длины нет.

До подтверждения баллы текущей версии равны нулю. Редактирование требует нового подтверждения; удаление сведений снижает рейтинг. AI формулу не изменяет. В ответе всегда итог, уровень, семь категорий с основаниями и список недостающих категорий.

Уровни: `draft` 0–39, `working` 40–69, `ready` 70–89, `priority` 90–100. Опубликованная задача любого уровня доступна всем командам. Каталог сортируется по опубликованному рейтингу и фильтруется по `topic` и `level`.

## Отклики, этап и баллы

Бизнес может выбрать ноль, одну или несколько команд. Выбор одного отклика не отклоняет остальные; автоматического назначения нет. Число откликов не ограничено. Идея/план/срок обязательны и непробельные; прототип необязателен, но непустая ссылка должна быть HTTP(S).

Один демонстрационный этап на выбранное предложение. Команда отправляет описание и ссылку; бизнес подтверждает либо возвращает с комментарием. Пересдача обновляет тот же ID. Подтверждение после возврата невозможно до пересдачи. После отправки результата менять выбор команды нельзя. Подтверждённый этап нельзя открыть повторно или заменить другим результатом. Повтор идентичного запроса возвращает прежний результат, параллельные запросы не создают дублей.

Подтверждение даёт 10 баллов, один раз. Это решение нашего backend-плана, не фиксированное число общего ТЗ. Кабинеты получают вложенный `milestone` из GET-списков предложений; команда дополнительно получает `team_points`. После перезапуска не требуется помнить ответы POST на клиенте.

## Демо и сброс

```powershell
py -m backend.seed
```

Первый запуск вставляет 5 черновиков, 5 карточек и 5 предложений. Повторный не затирает изменения. Профили команд доступны независимо от seed.

```powershell
py -m backend.seed --reset
```

**Внимание:** --reset заменяет только фиксированные demo-задачи из fixtures, но удаляет ВСЕ отклики и этапы, привязанные к этим demo-задачам. Созданные пользователем отдельные задачи сохраняются. Для чистой проверки используйте отдельный DATABASE_PATH, а не удаляйте рабочую базу.

Карточки fixtures имеют оценки 55, 75, 90, 100, 100. Поле rating в JSON — справочный снимок; seed пересчитывает его серверной формулой. Слабое описание в демонстрации ниже начинает с 10 и достигает 100.

## Демонстрация до пяти минут

1. В Swagger POST `/api/tasks`, заголовок `business-demo`:

```json
{"title":"Распределение обращений","topic":"Услуги","context":"Компания вручную распределяет обращения между сотрудниками."}
```

2. Скопируйте id. POST `/questions`: покажите не менее трёх вопросов и X-AI-Source. POST `/confirm`: исходный рейтинг 10. Это промежуточная фиксация для сравнения.
3. POST `/compose` с ответами:

```json
{"answers":[
 {"question":"Какую потребность нужно закрыть?","answer":"Сократить время распределения обращений."},
 {"question":"Кто будет пользоваться результатом?","answer":"Операторы службы поддержки"},
 {"question":"Какие данные и материалы уже доступны?","answer":"Обезличенные примеры обращений"},
 {"question":"Какие ограничения по срокам, бюджету и технологиям нужно учитывать?","answer":"Срок 7 дней; только обезличенные данные"},
 {"question":"Какой конкретный результат нужно передать заказчику?","answer":"Прототип регистрации и распределения обращений"},
 {"question":"По каким измеримым критериям будет оцениваться успех?","answer":"Распределить 100 заявок за 7 дней"},
 {"question":"Кто контактное лицо и как с ним связаться?","answer":"demo@example.com"},
 {"question":"Возможны ли консультации с экспертом и в каком формате?","answer":"Еженедельный созвон; обратная связь в Telegram"}
]}
```

4. Покажите редактируемый ответ. POST `/confirm`: 100 баллов с расшифровкой; POST `/publish`.
5. Переключите заголовок на `team-alpha`, GET `/api/tasks?topic=Услуги&level=priority`. POST `/api/tasks/{id}/proposals`:

```json
{"idea":"Распределение по категориям обращения","plan":"Определить категории, реализовать распределение, проверить на примерах","duration":"7 дней","prototype_url":"https://example.com/prototype"}
```

6. Бизнес: GET список предложений; POST `/api/proposals/{id}/decision`, `{"decision":"selected"}`. Можно продемонстрировать независимый выбор двух команд.
7. Команда: POST `/api/proposals/{id}/milestone`, `{"description":"Прототип","result_url":"https://example.com/result"}`. Бизнес: POST `/api/milestones/{id}/review`, `{"decision":"confirmed"}`. Повторите подтверждение; GET `/api/team/proposals` показывает ровно 10 баллов, а не 20.

Для возврата: `{"decision":"changes_requested","comment":"Добавьте проверку результата"}`, затем пересдача командой под тем же предложением. Подтверждённый результат уже нельзя вернуть.

## Проверки и отчёт по плану

```powershell
py -m unittest backend.test_tasks backend.test_ai backend.test_rating backend.test_workflow
```

На текущем наборе выполнено **38 тестов, OK**. Все используют временные БД или HTTP transport без внешнего провайдера; ключ пользователя не нужен.

- Карточки: права, null/неизвестные поля, подтверждение/публикация, неизменность публичного снимка при правках, снижение рейтинга и сохранение после запуска приложения.
- AI: все поля локальной сборки, три разных вопроса при одном отсутствующем поле, неверный JSON, отказ/обрыв/ошибки провайдера, отсутствие выдуманных цитат и сохранение отрицаний. Реальный compose проверен с источником openai; questions пока использует fallback из-за нарушения моделью лимита вопросов.
- Рейтинг: веса, подтверждение, пробелы, измеримость, контакты/взаимодействие, доступные значения и границы уровней, удаление сведений.
- Каталог/отклики: доступность низкого рейтинга, два независимых выбора, запрет чужих решений, пробельные строки, неверные ссылки/фильтры, единый формат 404.
- Этапы: запрет самопроверки и чужого бизнеса; комментарий возврата; пересдача того же этапа; запрет недопустимых переходов; восемь параллельных отправок и восемь подтверждений дают один этап и 10 баллов.
- Данные: повторный seed без дублей, reset сохраняет пользовательские задачи, миграция архивирует старые дубли этапов и не удваивает баллы.

### Исправление 1: уточнения к заполненным полям

Исправлен пропуск ответов при непустом целевом поле. API не изменён. Добавлены регрессионные проверки сохранения старых фактов и целого уточнения, повторной отправки без дубликатов, ответа/таймаута провайдера и отказа от ответа модели, потерявшего уточнение. Сквозная проверка через HTTP TestClient проходит цепочку: заполненная и опубликованная карточка → предлагаемый вопрос → ответ → оба текста в черновике → запрет публикации без подтверждения → подтверждение → повторная публикация. Публичный снимок не меняется до последнего шага.

Проверка: `py -m unittest backend.test_ai backend.test_tasks backend.test_workflow backend.test_rating` — **33 теста, OK**. Это не проверка внешнего OpenAI: успешный ответ провайдера здесь имитируется HTTP transport.

**HTTP-проверка на отдельном Uvicorn :8011:** черновик → 5 вопросов → compose → ручное подтверждение; рейтинг **10 → 100** → публикация → фильтр каталога → отклик → выбор → результат → возврат → пересдача того же ID → подтверждение → повторное подтверждение → **10 баллов**. Источник AI — fallback. После остановки/запуска процесса Uvicorn та же задача осталась опубликованной с рейтингом 100, этап confirmed, team_points=10. Пользовательская БД не использовалась и не удалялась.

### Проверка 4: источник AI и защита ключа

Первоначальная проверка до добавления ключа: с обычной конфигурацией backend, без подмены SDK и без принудительного отключения ключа, проверены `/questions` и `/compose` на синтетических сведениях во временной БД:

| Проверка | Результат |
|---|---|
| Ключ настроен | Нет; значение не выводилось |
| `/questions` | HTTP 200, `X-AI-Source: fallback`, 5 вопросов |
| `/compose` с непустыми ответами | HTTP 200, `X-AI-Source: fallback`, исходные факты и ответы сохранены |
| Подтверждение / публикация | Оба false |
| Доступность `X-AI-Source` через CORS | Подтверждена для обоих ответов |
| `.env` в Git | Исключён правилом ignore, не отслеживается |

`py -m unittest backend.test_ai` — **15 тестов, OK**. Проверяются успешные и отклонённые ответы модели, 401/429/500, таймаут, отсутствие повторов, сохранение уточнений и отрицаний. Все внешние ответы здесь имитированы транспортом SDK.

Для повторной проверки нужен настроенный `AI_API_KEY` либо `OPENAI_API_KEY`. По решению владельца QA получает `.env` вместе с веткой backend-mvp; не выводите ключ в чат или отчёты. После настройки перезапустите backend. Создайте синтетический черновик, вызовите `/questions`, передайте непустой ответ на предложенный вопрос в `/compose`. Оба ответа должны иметь `X-AI-Source: openai` и корректные тела; одного HTTP 200 недостаточно. Пустой список ответов в compose не вызывает модель. Заголовок `openai` означает успешную ветку SDK для настроенного `AI_BASE_URL`; для проверки именно OpenAI используйте `https://api.openai.com/v1`.

Первоначально ключ был записан в отслеживаемый `.env.example`. Настройки перенесены в `.env`, значения ключей в шаблоне восстановлены; на этом этапе секрет не включался в коммит. Позднее владелец явно потребовал включить `.env` в репозиторий для QA. Значение ключа в чат и этот отчёт не выводилось.

Результат реальных запросов после переноса: `/questions` — HTTP 200, fallback; `/compose` — HTTP 200, openai, ответы сохранены, confirmed=false, published=false. Для диагностики вопросов повторно вызван реальный SDK: JSON имеет верную структуру и 8 различных разрешённых вопросов; нарушен только лимит 3–5. Ответ провайдера не подменялся. Это известное ограничение для передачи QA, а не успешная проверка внешней генерации вопросов.
