# AI Sana — подготовка бизнес-задач и предложения студенческих команд

Команда **Bul Bul Corp**, хакатон HackAlem AI.

> **Состояние этой версии:** backend API 1.2 с регистрацией, входом, серверными сессиями, профилями и проверкой прав. Контракт для frontend: [аккаунты и профили](backend/ACCOUNTS.md). Порядок интеграции и показа: [передача и QA](backend/HANDOFF.md). Обычный режим использует cookie и CSRF; старый демозаголовок доступен только при DEMO_MODE=true. Финальная браузерная приёмка ожидает готовности экранов. Старый AI-ключ в истории Git требует отзыва.

## 1. Название проекта

**AI Sana**, репозиторий команды `hack-f035d723-bul-bul-corp`.

## 2. Какую проблему решает проект

Бизнес часто описывает потребность слишком общо: например, «обращения теряются между отделами». Студентам сложно понять, какие данные доступны, что именно нужно сделать и как будет оцениваться результат.

Проект помогает бизнесу структурировать задачу, увидеть недостающую информацию и опубликовать её в каталоге. Студенческие команды подают предложения, а бизнес самостоятельно выбирает исполнителей и подтверждает результаты этапов.

Основная геймификация направлена на **готовность задачи**, а не известность компании. Чем полнее подтверждённая карточка, тем выше её рейтинг и место в каталоге.

## 3. Что реализовано

- Личные аккаунты, вход и выход, сессии, смена пароля и редактируемые профили бизнеса/команды; серверная проверка прав через профиль пользователя.
- Создание и редактирование карточки задачи.
- Выбор 3–5 уточняющих вопросов по тем же правилам содержательности, что использует рейтинг. Неизвестные данные, пользователи, результат и критерии приоритетнее уточнений названия.
- Сборка редактируемой карточки: целые ответы добавляются к прежним сведениям, включая непустые поля. Неизвестные факты не выдумываются; требуется ручное подтверждение.
- Ручное подтверждение карточки и отдельная публикация.
- Рейтинг готовности 0–100 с расшифровкой категорий и списком недостающих сведений.
- Раздельное хранение текущей и опубликованной версий карточки и рейтинга.
- Общий каталог с сортировкой по убыванию опубликованного рейтинга и фильтрами по теме и готовности.
- Отклики команд: идея, план, срок, необязательная ссылка на прототип.
- Независимый ручной выбор или отклонение каждого предложения: можно выбрать несколько команд или не выбирать никого.
- Отправка результата этапа выбранной командой, подтверждение или возврат на доработку бизнесом.
- Запись 10 баллов за подтверждённый этап; повторное подтверждение того же этапа не увеличивает баллы.
- Хранение данных в SQLite между перезапусками.
- Проверки деморолей и принадлежности задач при изменении данных.
- Swagger UI, OpenAPI, структурированные ошибки и endpoint проверки состояния.

### Формула рейтинга

| Категория | Максимум | Фактическое правило |
|---|---:|---|
| Контекст и потребность | 20 | По 10 за сведения без явной неопределённости в `context` и `need` |
| Данные и материалы | 20 | Сведения без явной неопределённости в `data_materials` |
| Ожидаемый результат | 15 | Сведения без явной неопределённости в `expected_result` |
| Критерии успеха | 15 | Названный показатель с числовой целью и единицей, поддерживаемое количество объектов или результат со сроком |
| Ограничения | 10 | Сведения без явной неопределённости в `constraints` |
| Пользователи | 10 | Сведения без явной неопределённости в `users` |
| Связь с бизнесом | 10 | 5 за распознаваемый контакт + 5 за вид и канал/периодичность/доступность консультаций |

Принимаются `Снизить дефицит на 20%`, `Сократить потребление воды на 100 литров`, `Точность 90%`. Отдельные числа, даты, версии и `KPI 1` не засчитываются. «Не знаю» и другие распознаваемые сообщения о неопределённости не дают баллы; причины указаны в `basis`, неполные категории — в `missing`. Известные сведения в отдельных строках учитываются, даже если старое «не знаю» сохранено рядом. Это лексическая эвристика, не доказательство правдивости или достижимости. Название и тема не дают баллы.

До подтверждения все начисленные баллы равны нулю. Фактическое изменение полей сбрасывает подтверждение текущей версии; для начисления нужен новый вызов `/confirm`.

| Баллы | Значение API | Уровень |
|---|---|---|
| 0–39 | `draft` | Требует уточнения |
| 40–69 | `working` | Рабочая |
| 70–89 | `ready` | Готовая |
| 90–100 | `priority` | Приоритетная |

**Низкий рейтинг не запрещает публикацию подтверждённой карточки и отклики.** В каталоге отображается последний опубликованный снимок. После правок нужны `/confirm` и повторный `/publish`, чтобы обновить публичную карточку и её позицию.

## 4. Как работает решение

1. Представитель бизнеса выбирается через демоидентичность `business-demo` и создаёт задачу. Отдельного поля «исходный промпт» нет: проблему можно передать в `need` или `context`.
2. Endpoint `/questions` выдаёт вопросы для дополнения карточки.
3. Пользователь отправляет ответы в `/compose`, затем при необходимости исправляет поля через `PATCH`.
4. `/confirm` подтверждает сведения и рассчитывает рейтинг.
5. `/publish` сохраняет публичную версию; она появляется в каталоге.
6. Команда просматривает каталог и отправляет предложение.
7. Владелец задачи вручную выбирает или отклоняет предложение.
8. Выбранная команда отправляет результат этапа; бизнес подтверждает его или запрашивает доработку.
9. При подтверждении в записи этапа сохраняется `points_awarded: 10`.

Все эти действия доступны через API. Готовность пользовательских кабинетов frontend требует отдельной браузерной проверки вместе с этой версией backend.

## 5. Технологии

| Компонент | Технология |
|---|---|
| Язык | Python; код использует синтаксис Python 3.10+ |
| HTTP API | FastAPI `>=0.115,<1` |
| ASGI-сервер | Uvicorn с standard extras `>=0.30,<1` |
| Валидация и схемы | Pydantic `>=2.7,<3` |
| Хранилище | SQLite через стандартный модуль `sqlite3` |
| Документация API | OpenAPI и Swagger UI FastAPI |
| Внешние запросы | OpenAI SDK и HTTPX |
| AI-модель / внешний AI API | OpenAI-compatible Chat Completions, JSON-режим, проверка ответа и fallback |
| Frontend | Отдельная интеграция; в этом отчёте подтверждён backend, не готовность интерфейса |

Проверка текущего backend выполнялась на Python 3.14, FastAPI 0.135.1, Uvicorn 0.41.0, Pydantic 2.12.5 и HTTPX 0.28.1. Это проверенное окружение, а не lock-файл зависимостей.

## 6. Архитектура

```text
Swagger UI / HTTP-клиент / будущий frontend
                 |
                 | JSON + cookie + X-CSRF-Token
                 v
          backend/main.py
          маршруты и бизнес-логика
           /       |          \
          v        v           v
     schemas.py  rating.py   SQLite
     валидация   рейтинг    задачи, отклики, этапы
```

```text
backend/
  __init__.py
  main.py            # FastAPI, SQLite, маршруты и жизненный цикл
  schemas.py         # Pydantic-модели запросов и данных
  auth.py            # аккаунты, membership, cookie-сессии и профили
  account_schemas.py # приватные аккаунты и публичные профили
  rating.py          # Общие правила содержательности, рейтинг и уровни
  ai.py              # Вопросы, сборка карточки, внешний SDK и fallback
  seed.py            # Загрузка демонстрационных задач и откликов
  test_*.py          # Регрессии AI, рейтинга, карточек и этапов
  requirements.txt   # Зависимости
  CONTRACT.md        # Подробный контракт API
  README.md          # Конфигурация, промпты и отчёты backend
fixtures/            # demo-data.json и demo-identities.json
README.md            # Инструкция для жюри
```

SQLite хранит задачи, предложения и этапы; при миграции старые дубли этапов сохраняются в архивной таблице. Поля карточки и рейтинги хранятся в JSON-строках. Демопрофили загружаются из `fixtures/demo-identities.json`.

Основные группы API:
- `/api/tasks` — карточки и каталог;
- `/api/tasks/{id}/questions`, `/compose`, `/confirm`, `/publish` — подготовка и публикация;
- `/api/tasks/{id}/proposals` и `/api/proposals/{id}/decision` — отклики и выбор;
- `/api/proposals/{id}/milestone` и `/api/milestones/{id}/review` — результаты этапов;
- `/api/business/tasks`, `/api/team/proposals` — выборки для кабинетов;
- `/api/demo-identities`, `/api/health` — демопользователи и состояние сервиса.

Точные тела запросов: [backend/CONTRACT.md](backend/CONTRACT.md). В каталоге поле `rating` отражает публичный рейтинг; владелец в ответах редактирования получает рейтинг текущей версии. Контракт и заметки backend могут развиваться вместе с реализацией; описание выше сверено с текущим кодом.

## 7. Установка и запуск

### Требования

- Установленный Python и `pip`. Проверенное окружение — Python 3.14.
- Доступ к интернету для установки зависимостей и, при стандартной конфигурации FastAPI, загрузки ресурсов Swagger UI с CDN.
- Для локального fallback внешний AI-ключ не нужен. Для реального провайдера настройте новый ключ в локальном `.env`. Node.js, Docker и отдельный сервер БД для backend не требуются.

### Windows PowerShell

Откройте терминал в корне скачанного или клонированного репозитория:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend/requirements.txt
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

Активация окружения не требуется: используется прямой путь к его Python. При необходимости создайте локальный .env по .env.example; команды выше используют настройки по умолчанию.

### Linux / macOS

Из корня репозитория:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r backend/requirements.txt
.venv/bin/python -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

### Адреса после запуска

- Swagger UI: <http://127.0.0.1:8000/docs>
- OpenAPI: <http://127.0.0.1:8000/openapi.json>
- Проверка состояния: <http://127.0.0.1:8000/api/health>

Корневой маршрут `/` не содержит веб-приложения. Для остановки сервера нажмите `Ctrl+C`.

### Настройка SQLite

По умолчанию база создаётся в `backend/sana.sqlite3`. Корневой `.env` загружается автоматически; переменные процесса имеют приоритет. Основные настройки:

| Имя | Назначение |
|---|---|
| `DEMO_MODE` | По умолчанию false; true включает старые демоидентичности |
| `FRONTEND_ORIGINS` | Разрешённые Origin через запятую, по умолчанию localhost:5173 и 127.0.0.1:5173 с http |
| `COOKIE_SECURE` | Для HTTPS установить true; false только для локального HTTP |
| `DATABASE_PATH` | Путь к файлу SQLite вместо стандартного |
| `AI_API_KEY` / `OPENAI_API_KEY` | Локальный секрет провайдера; не коммитить |
| `AI_MODEL` | Модель, по умолчанию `gpt-4o-mini` |
| `AI_BASE_URL` | По умолчанию `https://api.openai.com/v1` |
| `AI_TIMEOUT_SECONDS` | Таймаут, по умолчанию 15 секунд; автоматических повторов нет |

Для независимой демонстрации задайте новый путь **до запуска сервера**:

```powershell
$env:DATABASE_PATH = Join-Path $env:TEMP ('sana-demo-' + [guid]::NewGuid().ToString() + '.sqlite3')
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --host 127.0.0.1 --port 8000
```

Родительская папка должна существовать. Чтобы начать с чистыми данными, остановите сервер и укажите другой новый файл; удалять рабочую базу не требуется. `.env.example` — шаблон с пустым ключом; локальный `.env` исключён из Git. Старый ключ ранее попал в историю Git: удаление файла не заменяет отзыв ключа у провайдера. После настройки нового ключа перезапустите backend.

## 8. Как проверить решение

### Демопользователи

Этот раздел и PowerShell-сценарий ниже используют отдельный деморежим. Перед запуском сервера установите `$env:DEMO_MODE = 'true'` в PowerShell либо `export DEMO_MODE=true` в bash. По умолчанию демовход отключён; для реальных аккаунтов используйте [ACCOUNTS.md](backend/ACCOUNTS.md). Не смешивайте демозаголовок и cookie аккаунта.

| Заголовок `X-Demo-Identity` | Роль |
|---|---|
| `business-demo` | Представитель бизнеса |
| `team-alpha` | Команда Альфа |
| `team-beta` | Команда Бета |

Заголовок обязателен для пользовательских операций; `/api/health`, `/api/demo-identities` и документация доступны без него. Это переключение демороли, а не вход с паролем.

Таблица показывает примеры идентичностей. Полный список: `GET /api/demo-identities` — два бизнеса и пять команд с профилями. Для наполнения отдельной демонстрационной БД выполните `py -m backend.seed` с тем же `DATABASE_PATH`, что использует сервер. Повторный seed не создаёт дубли. Не применяйте `--reset` к рабочей базе без понимания последствий; подробности — в backend/README.md.

### Воспроизводимый сценарий в PowerShell

Запустите сервер, затем откройте второй терминал PowerShell. Функция ниже отправляет JSON в UTF-8, чтобы кириллица корректно передавалась и в Windows PowerShell.

```powershell
$base = 'http://127.0.0.1:8000'
function Invoke-Sana {
    param([string]$Method, [string]$Path, [string]$Actor, $Payload = $null)
    $params = @{
        Method = $Method
        Uri = "$base$Path"
        Headers = @{ 'X-Demo-Identity' = $Actor }
    }
    if ($null -ne $Payload) {
        $params.ContentType = 'application/json; charset=utf-8'
        $params.Body = [Text.Encoding]::UTF8.GetBytes(
            (ConvertTo-Json -InputObject $Payload -Depth 10)
        )
    }
    Invoke-RestMethod @params
}

# 1. Черновик и уточняющие вопросы.
$task = Invoke-Sana POST '/api/tasks' 'business-demo' @{
    title = 'Маршрутизация обращений'
    topic = 'Поддержка'
    need = 'Обращения теряются при передаче между отделами'
}
$id = $task.id
Invoke-Sana POST "/api/tasks/$id/questions" 'business-demo'

# 2. Ответ пользователя попадает в карточку; ранее введённые сведения сохраняются.
Invoke-Sana POST "/api/tasks/$id/compose" 'business-demo' @{
    answers = @(@{
        question = 'Кто будет пользоваться результатом?'
        answer = 'Операторы поддержки'
    })
}
$weak = Invoke-Sana POST "/api/tasks/$id/confirm" 'business-demo'
$weak.rating.total # Ожидается 20.
Invoke-Sana POST "/api/tasks/$id/publish" 'business-demo'

# 3. Даже низкий рейтинг не мешает отклику.
$proposal = Invoke-Sana POST "/api/tasks/$id/proposals" 'team-alpha' @{
    idea = 'Автоматически распределять обращения'
    plan = 'Изучить синтетические примеры и подготовить прототип'
    duration = '2 недели'
    prototype_url = ''
}

# 4. Бизнес дополняет карточку собственными демонстрационными сведениями.
Invoke-Sana PATCH "/api/tasks/$id" 'business-demo' @{
    context = 'Операторы распределяют обращения вручную'
    data_materials = 'CSV с синтетическими обращениями и описание полей'
    expected_result = 'Прототип маршрутизации обращений'
    success_criteria = 'Снизить время обработки на 20%'
    constraints = '2 недели, обезличенные данные'
    contact = 'demo@example.com'
    consultation = 'Консультация раз в неделю'
}
$ready = Invoke-Sana POST "/api/tasks/$id/confirm" 'business-demo'
$ready.rating.total # Ожидается 100.
Invoke-Sana POST "/api/tasks/$id/publish" 'business-demo'
Invoke-Sana GET '/api/tasks?level=priority' 'team-alpha'

# 5. Бизнес вручную выбирает предложение.
Invoke-Sana POST "/api/proposals/$($proposal.id)/decision" 'business-demo' @{
    decision = 'selected'
}

# 6. Команда сдаёт результат этапа, бизнес подтверждает.
$milestone = Invoke-Sana POST "/api/proposals/$($proposal.id)/milestone" 'team-alpha' @{
    description = 'Подготовлен прототип на демонстрационных данных'
    result_url = 'https://example.com/demo-result'
}
$result = Invoke-Sana POST "/api/milestones/$($milestone.id)/review" 'business-demo' @{
    decision = 'confirmed'
}
$result # status: confirmed; points_awarded: 10.

# 7. Повторное подтверждение того же этапа оставляет 10 баллов, а не 20.
Invoke-Sana POST "/api/milestones/$($milestone.id)/review" 'business-demo' @{
    decision = 'confirmed'
}
```

`prototype_url` может быть пустым; `result_url` обязателен и должен быть HTTP(S)-адресом. Ссылка example.com в примере синтетическая и не утверждает наличие готового прототипа. Сервер проверяет формат, но не скачивает содержимое ссылки. При возврате этапа обязательно передать непустой `comment`; пересдача обновляет тот же ID.

Те же запросы можно выполнить через Swagger: выбрать endpoint, нажать **Try it out**, заполнить `x-demo-identity`, тело и выполнить запрос. Сохраняйте возвращаемые идентификаторы задачи, предложения и этапа.

### Фактически проведённая проверка

Сценарий выше выполнен как PowerShell-блок на отдельном Uvicorn (`127.0.0.1:8014`) и временной SQLite-базе, без изменения рабочей базы. Получены рейтинг **20 → 100**, подтверждённый этап и **10 баллов** после первого и повторного подтверждения. Внешний AI в том запуске не использовался. Исторический набор после AI-приёмки включал 43 теста. Текущая проверка аккаунтов описана в backend/README.md.

Отдельная реальная AI-приёмка 2026-09-23 на Uvicorn `127.0.0.1:8016` и временной БД: `/questions` — HTTP 200, openai, 5 разных содержательных вопросов; `/compose` с пятью ответами и отдельный compose с уточнением заполненного поля — HTTP 200, openai. Все 11 полей сверены точно: прежний текст, ответы, отрицания и условия сохранены, новых фактов нет. Автоматических подтверждения и публикации нет; уточнение после ручного подтверждения сбрасывает confirmed и рейтинг, публикация без повторного подтверждения возвращает 409. Использованы OpenAI `gpt-4o-mini` и существующий ключ по решению владельца; значение не выводилось и не возвращалось в Git. Подробности и исправленные причины fallback — в [backend/README.md](backend/README.md).

Регрессии запускаются командой:

```powershell
py -m unittest discover -s backend -t .
```

Проверки с MockTransport не являются проверками внешнего AI. Для повторной AI-приёмки вызовите `/questions`, затем `/compose` с непустыми ответами и проверьте `X-AI-Source: openai` в обоих ответах, сохранение уточнений и отсутствие неподтверждённых фактов. HTTP 200 с fallback — корректный локальный режим, но не успешный ответ внешней модели.

## 9. Данные и интеграции

- Данные задач, откликов и этапов вводятся через API и сохраняются локально в SQLite.
- `fixtures/demo-identities.json`: два бизнеса, пять команд с интересами, навыками и технологиями.
- `fixtures/demo-data.json`: пять исходных описаний, пять карточек и пять предложений; `backend.seed` загружает их с пересчётом рейтинга.
- OpenAI-compatible провайдер подключён через SDK. Входы, выходы, промпты и ошибки описаны в [backend/README.md](backend/README.md); исходные промпты — в `backend/ai.py`.
- `prototype_url` и `result_url` хранятся как ссылки; сервер не скачивает их содержимое.
- Вопросы и рейтинг используют общие правила достаточности сведений. Локальная сборка привязывает предлагаемые вопросы к полям; ответ к заполненному полю дополняет, а не заменяет прежний текст.
- `GET /api/team/proposals` возвращает `team_points`; GET-списки предложений содержат вложенный `milestone`, включая статус и комментарий возврата.

## 10. Ограничения текущей версии

1. **Frontend не принят совместно с backend:** требуется проверить кабинеты, ошибки и полный пользовательский путь в браузере.
2. **Риск опубликованного ключа не устранён:** реальная AI-приёмка пройдена с существующим ключом по решению владельца, только в памяти проверочного процесса. Это не отзыв секрета из истории и не проверка нового ключа. Будущие ответы модели могут нарушать контракт; сервер отклоняет их и честно возвращает fallback.
3. **Демоидентичность не является безопасной авторизацией:** заголовок можно выбрать вручную. Она работает только при DEMO_MODE=true. Обычный режим проверяет сессию и CSRF; CORS ограничен FRONTEND_ORIGINS.
4. **Эвристическая оценка:** общие правила неизвестности и измеримости не доказывают реальную доступность данных или достижимость результата. Человек проверяет и подтверждает карточку.
5. **Предложения не приватны между командами:** демокоманды могут читать предложения по опубликованной задаче. Используйте синтетические данные.
6. **Нет production-инфраструктуры:** чат, уведомления, файловое хранилище и полноценный трекер не входят в текущий backend. Регистрация и профили реализованы; приглашения участников и восстановление пароля по email пока отсутствуют. Новые подсистемы для исправлений QA не требуются.
