# Текущая работа

Покажи состояние workspaces. Не меняй файлы и не запускай проверки.

## Просмотр

1. Просмотри папки `ai/specs/` инструментами работы с файлами. Если папки нет или она пуста, скажи, что изменений пока нет, и предложи `/spec-kit specify <описание>`.
2. Для указанного workspace используй правила выбора из SKILL.md. Для списка просмотри каждый workspace отдельно.
3. Прочитай spec, план и задачи по мере необходимости. Выведи следующий шаг по таблице SKILL.md. Учитывай содержимое и блокеры, а не только имена файлов.
4. В `tasks.md` посчитай статусы для ответа, но не записывай счётчики в файл. Назови первую допустимую задачу в порядке документа. `in_progress`, `blocked`, незакрытые зависимости или неподтверждённые границы не означают готовность к запуску.
5. Несоответствие текущему формату, неизвестный статус, повторяющийся ID или отсутствующую зависимость покажи как проблему. Не исправляй её на этапе просмотра.

Если несколько workspaces готовы к продолжению, покажи варианты. Не выбирай за пользователя. Готовые к продолжению показывай первыми, завершённые описывай кратко. На запрос полного списка не скрывай завершённые.

## Ответ

Для каждого изменения достаточно пути, следующего шага и причины. Если есть задачи, добавь число выполненных и ближайшую задачу. Пример:

```text
ai/specs/2026.09.21_10-30_csv-export
Выполнено 1 из 3 задач. Следующая T002, экспорт выбранных записей.
Продолжить: /spec-kit implement ai/specs/2026.09.21_10-30_csv-export
```

Без аргументов предложи подходящее действие. Если работа ещё не выбрана, кратко перечисли specify, plan, tasks, implement, verify и list. Не создавай файлы и не начинай предложенное действие без запроса.
